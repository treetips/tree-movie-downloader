# ダウンロード結果に動画タイトルとサムネイルを表示する

- ステータス: Accepted
- 決定日: 2026-11-27
- 影響範囲: 一括ダウンロード、かんたんダウンロード、キュー、yt-dlp連携

## 背景

[かんたんダウンロードを既存キューへ自動登録する](./0004-easy-download.md)では、タイトル・サムネイル取得を初回実装の対象外としていた。ダウンロード完了後、URLだけではどの動画を保存したのかを確認しにくいため、両画面で動画タイトルとサムネイルを表示する必要がある。

YouTube APIは引き続き使用しない。yt-dlpはダウンロード時にタイトル・サムネイル・保存先を取得しているため、この情報を画面表示へ再利用する。

## 決定

- 一括ダウンロードでは、完了・スキップ済み項目のURL列を動画タイトルとサムネイル表示へ切り替える。メタデータを取得できない場合はURLをフォールバックとして表示する。
- かんたんダウンロードでは、完了・スキップ済み項目の再生・保存先を開く操作の上に、動画タイトルとサムネイルを表示する。
- タイトル・サムネイル・保存先は、yt-dlpの機械可読な出力から取得し、既存キューへ保持する。保存済みファイルをスキップする場合も、既存のメタデータ確認で取得した情報を利用する。
- プレイリスト・チャンネルURLは項目を動画単位へ展開せず、最初に成功した動画のタイトル・サムネイルを代表表示とする。
- サムネイル画像はバックグラウンドで取得し、表示用に縮小してPNGへ正規化する。取得・変換に失敗してもダウンロード結果は失敗とせず、タイトルだけを表示する。
- タイトル・サムネイルは完了・スキップ済みの状態でのみ表示し、再試行・再開時に前回の結果情報をクリアする。

## 理由

yt-dlpの出力を利用すると、YouTube APIや別のメタデータ取得処理を追加せず、動画単位・コレクションURLのいずれでも同じキュー状態へ結果を反映できる。画像を取得してから表示用画像へ変換すると、GPUIのHTTPクライアント設定に依存せず、表示サイズより大きい画像のデコードメモリも抑えられる。

コレクションURLを代表表示にすることで、既存の「URL単位のキュー」というモデルを維持したまま、完了後に動画を識別できる。

## 結果

- 両画面で、ダウンロード対象の動画をタイトルとサムネイルで確認できる。
- メタデータやサムネイルの取得失敗は、保存済みファイルの再生・保存先を開く操作を妨げない。
- 一括ダウンロードのURL列は、メタデータ取得後のほうが最小幅を必要とする。
- プレイリスト・チャンネルURLの行は、そのコレクション全体ではなく代表動画の情報を表示する。

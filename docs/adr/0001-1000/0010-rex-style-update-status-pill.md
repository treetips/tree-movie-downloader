# 更新通知をRex風のステータスピルにする

- ステータス: Accepted
- 日付: 2026-11-27
- 更新通知の配置と余白は [ADR 0012](./0012-align-update-area-with-toolbar.md) で置換
- 配色は [ADR 0018](./0018-update-notification-contrast.md) で置換
- アプリ更新後の再起動は [ADR 0020](./0020-user-initiated-app-relaunch.md) で置換

## 背景

更新通知をタイトルバー右端へ置くと、ウィンドウ幅やツールバー項目の影響を受けてラベルや操作ボタンが圧縮され、状態と次の操作が分かりにくくなる場合があった。また、更新ありの表示全体が操作ボタンになっており、通知を閉じる操作もなかった。

Superlogical Rex の更新通知は、状態アイコン・本文・操作・閉じるを固有サイズのカプセル内に分け、ヘッダー下の右上へ配置している。

## 決定

- 更新通知はヘッダー下の右上へ重ね、ツールバーの圧縮に任せず固有サイズのステータスピルとして表示する。全幅には広げない。
- ピル内は、円形背景の状態アイコン、ステータス本文、操作ピル、円形の閉じるボタンをこの順に並べる。
- 更新ありは本文クリックではなく、`インストール` の操作ピルから既存の確認ダイアログを開く。更新の実行順序と Release 分離は [ADR 0003](./0003-independent-app-and-library-updates.md) のまま維持する。
- 更新あり・更新なし・インストール失敗は閉じるボタンで通知だけを非表示にする。閉じても更新の状態自体は保持し、About 画面には引き続き表示する。再確認・再実行時には通知を再表示する。
- 確認中・インストール中は、進捗や状態を失わないよう閉じるボタンを表示しない。
- ダウンロード中は円形の進捗表示と右端の百分率を使い、検証・展開・配置中は円形の不確定表示と段階名を使う。
- ピルの背景は GPUI Kit のテーマトークンを半透明にして重ね、更新ありを青、インストール失敗を赤、更新なしの状態アイコンを緑で示す。状態はアイコン・本文・操作でも区別し、色だけに依存させない。
- 本文の上余白を12px相当とし、通知との近接を解消する。

## 代替案

- ツールバーの圧縮に任せる
  - 却下: ウィンドウ幅やツールバー項目によって本文・操作部が消えるため。
- 更新ありの表示全体を操作ボタンのままにする
  - 却下: 状態・操作・閉じるを区別できず、誤操作も増えるため。
- 更新通知をモーダルやサイドナビへ戻す
  - 却下: ヘッダーで状態を確認し、同じ場所で操作するRexの体験と異なるため。
- 閉じる操作で更新の状態自体を消す
  - 却下: About 画面の表示と実際の更新状態が食い違い、再実行や今後の確認に支障が出るため。

## 結果

- 更新通知はウィンドウ幅が変わっても本文と操作部を維持する。
- 状態アイコン・操作ピル・閉じるボタンが重ならず、Rexに近い外観になる。
- 本ADRは ADR 0003 の更新通知UIに関する部分を置き換える。アプリとライブラリの独立更新、ライブラリ→アプリの実行順序、配布形態は変更しない。

# Denoを管理対象ツールとして配布する

- ステータス: Accepted
- 日付: 2026-11-28

## 背景

yt-dlp は YouTube の JavaScript challenge を解消するために Deno などの外部ランタイムを必要とする。Deno が Homebrew でインストールされていても、Finder から起動したアプリの PATH には `/opt/homebrew/bin` が含まれず、YouTube の動画形式を取得できない場合がある。フルディスクアクセスはこの問題を解決しない。

既存のツール管理は yt-dlp と ffmpeg/ffprobe を GitHub Releases から取得し、SHA-256 を検証して配置する仕組みである。Deno も同じ更新・配布経路に含めれば、利用者の PATH や別途インストールに依存せず、yt-dlp の要件変更にも追従できる。

## 決定

- Deno を yt-dlp・ffmpeg/ffprobe と並ぶ必須ツールとして `tools-latest` の `tools-info.json` で管理する。
- Deno は公式 Releases のプラットフォーム別 ZIP から実行ファイルを取得し、ライセンスを添えて既存と同じ ZIP 形式で再配布する。取得時に SHA-256 を検証し、管理下のディレクトリへ配置する。
- yt-dlp の実行時は、管理下の Deno の絶対パスを `--js-runtimes deno:<path>` として明示する。開発時は PATH や一般的なインストール先へのフォールバックを許可する。
- Deno も既存のライブラリ更新の対象とし、About 画面にバージョンを表示する。
- manifest とローカル記録の `schemaVersion: 1` は維持する。古いアプリは未知の Deno エントリを無視するため、配布情報へ先に追加しても既存アプリの起動を妨げない。
- Deno を含むツール配布を先に公開し、その後に Deno を必須とするアプリを公開する。逆順では新しいアプリが古い配布情報を拒否する。

## 理由

Deno をアプリが明示的に管理することで、Finder 起動時の PATH 差や利用者ごとのインストール状況を吸収できる。既存のツール更新経路に含めることで、Deno 単体の更新も利用者の確認後にインストールでき、配布物の完全性検証も統一できる。

## 結果

- 利用者は Deno を別途インストールしなくても YouTube の challenge を解消できる。
- 初回起動や Deno の更新時には、公式 ZIP に相当する約 40 MB の追加ダウンロードが発生する。
- 既存の yt-dlp・ffmpeg だけがインストール済みの環境では、次回起動時に Deno だけを追加取得する。
- アプリとツールのリリース順序に依存するため、Release Tools を先に実行する運用を文書化する。

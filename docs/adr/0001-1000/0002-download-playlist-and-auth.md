# 動画URLのプレイリスト指定とYouTube認証の扱い

- ステータス: Accepted
- 日付: 2026-11-23

## 背景

- YouTubeの動画URLには、視聴中に開いていたミックスやプレイリストの `list` パラメータが付くことがある。
- 従来はURLをそのままyt-dlpへ渡していたため、`https://youtu.be/...?list=...` のようなURLでミックス全体の取得が始まり、1件のキュー項目として長時間動き続けていた。
- ダウンロード全体に60秒の固定タイムアウトを設けていたため、長時間の取得やffmpegによる変換が失敗扱いになっていた。
- YouTubeが「ロボットでないことを確認」を求めた場合、従来は環境変数 `YT_DLP_COOKIES_FROM_BROWSER` の設定が必要で、GUIから設定できなかった。
- yt-dlpの進捗は標準出力へ出るが、`--print` が `--quiet` を暗黙に有効にするため進捗が出力されず、画面の進捗が更新されていなかった。

## 決定

- 動画URLに `list` パラメータが付いている場合は `--no-playlist` を付けて、その動画だけを取得する。プレイリストURLとチャンネルURLは従来どおり複数件の取得を許可する。
- yt-dlpのタイムアウトは全体時間ではなく、出力が途切れた時間で判定する。進捗・標準出力・標準エラーが3分間なければ停止する。
- `--no-quiet` と目印付きの進捗テンプレートを使い、標準出力から進捗と保存先を取得する。
- レート制限（HTTP 429）は即座に失敗とせず、15秒待って設定された回数まで再試行する。
- 設定画面に「ブラウザのCookie」を追加し、`--cookies-from-browser` へ渡す。環境変数が設定されている場合は環境変数を優先する。
- yt-dlpの警告は、その項目のサイトのログへ残す。

## 影響

- 動画URLに `list` が付いていても、意図せずミックス全体を取得しない。
- プレイリスト全体を取得したい場合は、`/playlist?list=...` 形式のURLを追加する必要がある。
- ブラウザのCookieを読むには、macOSの権限（Safariはフルディスクアクセスなど）が必要になる場合がある。
- 3分間出力がない場合だけ失敗するため、長時間のダウンロードや変換が途中で打ち切られない。

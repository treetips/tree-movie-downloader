# アプリとライブラリの更新

## 更新の条件

### アプリ本体

- アプリケーションのセマンティックバージョンと、公開先の `update-info.json` が示す最新バージョンを比較し、新しいバージョンが見つかるかどうかで判定します。
- 比較するのは `Major.Minor.Patch` の3要素です。プレリリース表記やビルド番号は現時点では扱いません。

### ライブラリ

- ライブラリは yt-dlp・ffmpeg（ffprobe を含む）・Deno を対象にします。
- `tools-info.json` の `version` / `platform` と、ローカル記録 `.installed.json` の `version` / `platform` を比較します。
- 記録が配布情報と一致していても、対象バイナリが実行可能なファイルとして存在しなければ更新対象にします。同じバージョンでも欠落や破損を修復するためです。
- 更新対象だけをダウンロードし、SHA-256 を検証して置換します。
- manifest schema と installed schema は変更せず、`schemaVersion: 1` を維持します。

## 仕組み

- 配布物は **GitHub Releases** にホストします。
  - アプリ更新情報: `https://github.com/treetips/tree-movie-downloader/releases/latest/download/update-info.json`
  - アプリ本体: `https://github.com/treetips/tree-movie-downloader/releases/download/<tag>/Tree-Movie-Downloader-v<version>-macos.zip`
  - ライブラリ情報: `https://github.com/treetips/tree-movie-downloader/releases/download/tools-latest/tools-info.json`
- アプリの `update-info.json` は `version` / `url` / `sha256` を持ちます。アプリは `url` の ZIP をダウンロードして SHA-256 を検証し、ZIP 内の `.app` を展開・検証して実行中のアプリと置き換えます。
- ライブラリの `tools-info.json` は、ツール名・バージョン・プラットフォーム・URL・SHA-256・必須フラグを持ちます。アプリは現在の OS / CPU に合うエントリだけを選び、更新対象の ZIP を検証・展開して管理下のツールを置き換えます。
- アプリ本体とライブラリは独立して配布・確認・インストールします。更新の自動インストールは行いません。

## 更新確認の起動経路

### アプリケーション起動時

- アプリ本体をバックグラウンドで確認します。ダイアログは表示せず、更新が見つかった場合はヘッダー下の右上の更新ステータスピルに反映します。
- ツール準備が完了した後に、ライブラリも1回だけバックグラウンドで確認します。準備画面が表示された場合も、準備完了後までライブラリの更新確認は開始しません。
- ツールがそろっている通常起動でも、アプリ本体とライブラリの更新確認は行います。この通信は不足ツールの準備処理とは別です。

### メニューバー

- macOS メニューバーの `TreeMovieDownloader` → `アップデートを確認` から手動で確認します。
- アプリとライブラリの両方を確認し、結果を集約して1つのダイアログで通知します。
- 片方の確認に失敗しても、成功した側の更新情報・最新状態を保持します。失敗内容はダイアログで通知し、成功した側の結果を消しません。
- どちらかの確認が失敗している間は、更新ステータスピルを表示しません。成功した側の更新は About 画面から操作できます。

### About画面

- `アップデートを確認` ボタンから、メニューバーと同じ手動確認を行います。
- アプリ更新とライブラリ更新の状態は別々に表示します。更新がある場合はそれぞれの `インストール` ボタンも表示します。

## インストールの流れ

- 更新は、実行中のダウンロードを停止してから開始します。更新中はキューの新規開始・再開を無効にします。
- 確認ダイアログは表示時点の更新対象を保持し、インストール前に更新対象が変わっていれば再確認します。

1. ヘッダー下の右上にある更新ステータスピルの `インストール` をクリックすると、利用可能な更新をまとめた確認ダイアログを開きます。
2. ダイアログの `インストール` をクリックするとダイアログが閉じ、更新ステータスピルがインストールの進捗表示に変わります。
3. アプリとライブラリの両方がある場合は、先に更新対象のライブラリをダウンロード・検証・配置します。
   - ライブラリの更新に失敗した場合はアプリ更新を開始しません。
   - ライブラリの更新がすべて成功した場合だけ、続いてアプリ本体を更新します。
4. アプリ本体はダウンロード後に SHA-256 を検証し、ZIP を展開して `.app` を置き換えます。
   - ダウンロード中は円形の進捗表示と受信バイト数に基づく進捗率（%）を表示します。
   - 検証・展開・配置中は円形の不確定表示で段階を表示します。
5. アプリ更新が成功すると、配置完了状態を保持し、緑の完了表示と `再起動` ボタンを表示します。この時点では自動起動・自動終了しません。
6. 利用者が更新ステータスピルまたは About 画面の `再起動` ボタンを押すと、新しいアプリを起動して旧プロセスを終了します。再起動に失敗した場合は旧アプリへロールバックし、`再実行` から再更新できます。
7. ライブラリだけを更新する場合は、完了後に通知を表示し、アプリは再起動しません。
8. 失敗した場合は赤い `インストールに失敗` のステータスピルへ切り替わり、`再実行` で更新をやり直せます。
   - 両方を更新する計画でライブラリが失敗した場合、再実行後もライブラリの成功を確認してからアプリ更新を開始します。
9. 開発ビルドなど、実行中のアプリが `.app` の中にない場合は終了せず、展開したアプリを Finder で表示します。

## 更新ステータスピル仕様

- 更新通知はヘッダー下の右上へ重ね、固有サイズのカプセルとして表示します（[ADR 0010](../../adr/0001-1000/0010-rex-style-update-status-pill.md)）。
- 左端に円形背景の状態アイコン、中央にステータス本文、右端に操作ピルと円形の閉じるボタンを置きます。
- 背景は GPUI Kit のテーマトークンを半透明にして重ね、テキストと境界で状態を識別できるようにします。
- 左のツールバーと同じ高さの行内で中央揃えにし、行の外側に追加の余白は設けません。

### 更新が有る場合

ステータス本文は、次の3種類に限定します。

| 更新の状態               | ステータス本文                       |
| ------------------------ | ------------------------------------ |
| アプリとライブラリの両方 | `アプリとライブラリの更新が有ります` |
| アプリのみ               | `アプリの更新が有ります`             |
| ライブラリのみ           | `ライブラリの更新が有ります`         |

- 本文はクリックせず、右端の `インストール` から利用可能な更新をまとめた確認ダイアログを開きます。
- 実行中のダウンロードがある間は、操作ピルを無効化します。
- 閉じるボタンで通知だけを非表示にします。更新の状態自体は保持し、About 画面や再確認では引き続き利用できます。
- 状態アイコンと操作ピルにはテーマトークン（blue）を使います。

### 確認中の場合

- `アップデートを確認中` と円形の不確定進捗を表示します。
- ステータスピルはクリックできず、閉じるボタンも表示しません。

### インストール中の場合

- ヘッダー下の右上に円形の進捗表示と段階名を表示します。
- ダウンロード中は `ダウンロード中` と円形の確定進捗、右端に `42%` を表示します。総バイト数が不明な場合は円形の不確定進捗にします。
- ライブラリは対象ツール名と工程数、アプリは `ダウンロードを検証中`・`展開中`・`アプリを配置中` を表示します。
- ステータスピルはクリックできず、進捗を失わないよう閉じるボタンも表示しません。
- 失敗時は背景を赤色にした `インストールに失敗` のステータスピルへ切り替えます。
  - ピル内に `再実行` ボタンを表示し、クリックすると更新をやり直します。
  - 閉じるボタンで通知だけを非表示にできます。失敗の詳細理由はエラーダイアログと About 画面のメッセージに表示します。
- インストール中は手動の更新確認を無効化します。

### アプリ更新が完了した場合

- 緑の状態アイコンと `アップデートが完了しました` を表示します。
- `再起動` ボタンを押したタイミングで、配置済みの新しいアプリを起動して旧プロセスを終了します。
- 閉じるボタンで通知だけを非表示にできます。再起動が必要な状態は保持し、About 画面からも `再起動` できます。
- 再起動に失敗した場合は旧アプリへロールバックし、エラーダイアログを表示して `再実行` から再更新できます。ダウンロード実行中は再起動ボタンを無効化します。

### 更新が無い場合

- ヘッダー下の右上に `アップデートは有りません` と緑の状態アイコンを表示します。
- 閉じるボタンで非表示にし、10秒後にも自動的に非表示になります。
- 背景色は控えめな色、テキスト色は通常の本文色で表示します。

## 配布・設定

### 更新ホスト（GitHub Releases）

- GitHub Releases のアセットはフラットで、ネスト階層を配信できません。
- Release ワークフロー（`.github/workflows/release.yml`）は、手動インストール用の `Tree-Movie-Downloader-v<version>-macos.zip`、`SHA256SUMS.txt`、`update-info.json` を同じ Release に添付します。
- アプリは GitHub Releases の最新 Release から `update-info.json` を取得します。
- ライブラリは `tools-latest` で配布します。このリリースは pre-release のため、アプリ本体の「Latest」を隠しません。

### 初回リリース時の注意

- 初回は比較元となる `update-info.json` が存在しないため、Release ワークフローが初回用の `update-info.json` を生成します。2回目以降は公開済みの最新リリースを基準に更新します。

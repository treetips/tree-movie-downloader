# トップメニュー

> 画面上部のメニューと画面切り替え、タイトルバー右端の更新エリアは実装済みです。

## メニュー

ウィンドウ上部に、アイコンとラベルを並べたメニューを表示します。選択中の画面は背景色で示します。

- [一括ダウンロード](./batch-download.md)
- [かんたんダウンロード](./easy-download.md)
- [設定](./settings.md)
- [About](./about.md)

## 画面

- 一括ダウンロード: キューとログを表示します。
- かんたんダウンロード: 動画URLを1件入力し、保存先を確認してすぐに開始できます。
- 設定: アプリ全体の設定とダウンロードの共通設定を表示します。
- About: アプリ名、アイコン、バージョン、GitHub、Copyright、yt-dlp と ffmpeg のバージョン、アプリ更新とライブラリ更新の状態を表示します。

## タイトルバー

- 左側にアプリアイコンとアプリ名を表示します。
- 右端にバージョンとアップデートエリアを表示します。
- アップデートエリアは、macOSの閉じるボタンがあるタイトルバーの右端に置きます。
- その下のページ切り替えメニュー行は、GPUI Kitのテーマトークン（group_box）を背景色にして、上下の領域との境界を分かりやすくします。

## アップデート通知

- アプリ本体とライブラリ（yt-dlp、ffmpeg/ffprobe）を独立した更新として扱い、更新の自動インストールは行いません。
- 表示のきっかけは、次のとおりです。
  - アプリケーション起動時: アプリ本体をバックグラウンドで確認する。
  - ツール準備完了後: ライブラリを1回だけバックグラウンドで確認する。ツールがそろっている場合も実行する。
  - About 画面の `アップデートを確認`・メニューバーの `アップデートを確認`: アプリとライブラリの両方を手動確認し、結果を集約して1つのダイアログで通知する。片方の確認失敗で、成功した側の結果を消さない。

### 更新確認中の場合

- `アップデートを確認中` とスピナーを表示します。
- エリアはクリックできません。

### アップデートが有る場合

更新ボタンの文言は、次の3種類に限定します。

| 更新の状態               | ボタン文言                           |
| ------------------------ | ------------------------------------ |
| アプリとライブラリの両方 | `アプリとライブラリの更新が有ります` |
| アプリのみ               | `アプリの更新が有ります`             |
| ライブラリのみ           | `ライブラリの更新が有ります`         |

- クリックすると、利用可能な更新をまとめたインストール確認ダイアログを表示します。
- 両方ある場合は、ダイアログの `インストール` からライブラリ→アプリの順に更新する。ライブラリの更新に失敗した場合はアプリ更新を開始しない。
- アプリ更新が成功すると再起動する。ライブラリだけの更新では再起動しない。
- GPUI Kitのテーマトークン（blue）を使った青い塗りつぶしボタンで表示します。
- ホバー・フォーカス・キー操作でも、クリックできるボタンとして状態が分かるようにします。

### インストール中の場合

- インストール開始後は `インストール中` を表示します（確認ダイアログは閉じます）。
- ダウンロード中は `ダウンロード 42%` のような進捗率とプログレスバーを表示します。
- 検証・展開・コピー中は段階に応じた文言と不確定バーを表示します。
- エリアはクリックできません。アプリ更新の完了時は新しいバージョンで再起動して終了し、ライブラリだけの完了時は再起動せず通知を表示します。
- 失敗時は背景を赤色にした `インストールに失敗` エリアに切り替え、中の `再実行` で更新をやり直せます。

### アップデートが無い場合

- `アップデートは有りません` を表示します。
- クリックすると更新エリアを非表示にします。10秒後には自動的にも非表示になります。
- 背景色は透明で目立たない色にします。

## サイドナビを使わない理由

- サイドナビは横幅を260px使うため、キュー表の表示幅を圧迫していました。
- 画面数が4つと少なく、アイコン付きの横並びメニューでも識別できます。
- サイドナビを外したぶんを、キューのURL列と操作列に充てられる。

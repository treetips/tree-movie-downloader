# ツール準備画面

> 初回起動時など、yt-dlp・ffmpeg・Deno が揃っていないときに表示します。日常の更新確認とは分けて扱います。

## 目的

- 利用者に、アプリが外部ツールを取得していることを伝える。
- ダウンロードの進み具合と、失敗したときの次の操作を示す。
- 準備が完了するまで、キューの操作や設定変更をさせない。

## 表示条件

- 起動時に `~/.config/tree-movie-downloader/tools/` 配下の yt-dlp・ffmpeg・ffprobe・Deno を確認する。
- すべて実行可能なファイルとして揃っていれば表示せず、そのままメイン画面を表示する。このツール準備処理では通信しない。
- 1つでも欠けていれば表示し、不足・更新対象のツールを取得して、完了するまでトップメニュー・キュー・ステータスバーを隠す。
- タイトルバーは残し、ウィンドウの移動・最小化・閉じる操作を妨げない。

## 更新確認との分離

- 起動時のアプリ本体更新確認は、ツール準備とは独立してバックグラウンドで開始する。
- ライブラリの更新確認は、ツール準備が完了した後に1回だけバックグラウンドで開始する。準備に失敗している間は開始しない。
- ツールがそろっている場合も、準備処理では通信しないが、日常の更新確認のための通信は行う。
- 更新確認で更新が見つかっても自動インストールしない。ヘッダー下の右上の更新ステータスピルにある `インストール…` から確認ダイアログを開き、利用者がインストールを選ぶ。
- この画面は不足ツールの準備と再試行を担当し、日常更新の確認ダイアログやインストール進捗は担当しない。

## レイアウト

- コンテンツ領域の中央にカードを1枚表示する。
- カードの幅は最大 `560px` とし、ウィンドウが狭い場合は収める。
- 左上にダウンロードのアイコン、その右にタイトルと説明を置く。
- カード下部に補足文と、失敗時だけ `再試行` ボタンを置く。

## 状態

### 確認中

- スピナーと `配布情報を確認しています…` を表示する。

### ダウンロード中

- 対象ツール名と `ダウンロードしています` を表示する。
- 受信バイト数と Content-Length から進捗バーを表示する。
- Content-Length が無い場合は不確定の進捗バーにする。
- 受信済みサイズと全体サイズ、`1 / 3` のような工程数を表示する。

### 配置中

- 対象ツール名と `配置しています…` を表示する。
- 進捗バーは不確定表示にする。
- 配置前にダウンロードした ZIP の SHA-256 を検証する。

### 失敗

- 赤い枠の領域に、失敗した理由と `ネットワーク接続を確認して、再試行してください。` を表示する。
- `再試行` ボタンを表示し、クリックすると確認中からやり直す。

### 完了

- 画面を閉じ、メイン画面を表示する。
- ライブラリのバックグラウンド更新確認を1回開始する。更新が見つかっても自動インストールしない。

## 文言

- タイトル: `動画ツールを準備しています`
- 説明: yt-dlp・ffmpeg・Deno のうち、未準備・更新対象のツールを GitHub Releases から取得します。日常の更新確認とは分けて扱い、更新の自動インストールはしません。
- 補足: `準備が完了すると自動的にメイン画面へ進みます。`
- 再試行: `再試行`
